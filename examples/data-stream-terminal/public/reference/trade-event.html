Trade Event Reference

Trade events share one public schema, but the actual value strength depends on the pool family and the transport path. Clients must not flatten those differences away.

Supported trade paths

Pool family Transport Current state

meteora-dbc / bags-fm parsed_tx Production trade path is runtime-enabled, but field strength is weaker than pump and launchpad paths.

Key rule

Mint is mandatory

  • If mint cannot be proven from the current trade payload, the event should not be emitted.
  • Clients should never expect backfilled mint enrichment on trade events.

Letsbonk boundary

creatorFeeAddress is conditional

Allowed path A narrow runtime cache may supply creatorFeeAddress for letsbonk trades.
Cold runtime On cache miss or cold start the field remains null by contract.
Client rule Null must be treated as valid, not as a server failure.

Current expectations

Safe trade parsing

  • Read source and pool together.
  • Branch on quoteMint. Non-SOL trade paths should use quoteAmount, quoteInPool, vQuoteInBondingCurve, and marketCapQuote.
  • Do not assume marketCapSol exists for every trade family, but for pump logs_only it can now be computed directly from the current virtual curve payload with documented mode-aware supply: legacy 1B, mayhem create_v2 2B.
  • Do not assume creatorFeeAddress is stable across runtime restarts.
  • Do not expect mint-level token config fields inside trade events.
