Migration Event Reference

Migration is not a logs-only event path. The current public implementation uses lifecycle detection from logs and then resolves the event from the parsed transaction of that same migration transaction.

What is intentionally excluded

Not currently promised

  • marketCapSol
  • poolFeeRate
  • supply
  • burnedLiquidity
  • creatorFeeAddress
  • mintAuthority and freezeAuthority

Implementation rule

Why parsed_tx is used

  • Lifecycle logs are used as the trigger.
  • The final event is derived from the current parsed transaction.
  • No historical cache enrichment is required.
  • No metadata backfill is part of the migration contract.

Client guidance

How to consume migration safely

  • Read pool plus poolCreatedBy together.
  • Do not assume every migration family exposes the same extra economics.
  • Use source to distinguish parsed-tx migration from logs-only trade paths.
