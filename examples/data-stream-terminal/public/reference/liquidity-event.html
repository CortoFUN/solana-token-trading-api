Liquidity Event Reference

Liquidity events cover both add and remove directions through one schema. Clients should route by txType instead of assuming one direction from the page alone.

Contract

Current public schema

  • schemaVersion: liquidity_event_v1
  • source: parsed_tx
  • txType: add or remove
  • tokensInPool and solInPool are allowed only when derivable from the current parsed transaction.

Guaranteed core

Fields clients can rely on

  • signature, mint, txType, pool, poolId
  • source, slot, block, poolProgramId, instructionName, hasError
  • baseVault, quoteVault, baseMint, quoteMint
  • baseAmount, quoteAmount, tokensInPool, solInPool

Conditional values

Do not over-assume

  • poolCreatedBy can stay null unless lineage is proven.
  • lpMint and lpAmount are allowed but not universally guaranteed.
  • The same schema covers both add and remove; always branch by txType.
