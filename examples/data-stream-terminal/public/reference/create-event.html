Create Event Reference

Create events are designed to answer a practical question quickly: what was launched, how early is the position, and which values are safe for filtering or ranking.

Overview JSON contract Create Trade Migration CreatePool Liquidity Burn

Detail levels

One create stream, multiple payload levels

Level Meaning
min Smallest public create payload for feed routing and fast inspection.
mid min plus market, token, risk basics, and quote-aware create market cap fields.
full min plus mid plus the rich public create shape. 
{
  "type": "subscribe",
  "mode": "mints",
  "create": {
    "detail": "mid"
  }
}

Field groups

How create fields are organized

Group Use
Core Fields that are meant to support strategy, alerting, and routing.
Extended Useful fields that can be null or pool-specific.
Service Additional analytics or pool-specific fields that stay out of the baseline public contract.

Commonly useful values

Fields clients usually care about first

  • mint, pool, poolProgramId
  • price, initialBuy, and solAmount only when the quote mint is SOL
  • tokensInPool plus either solInPool or quoteInPool depending on quoteMint
  • vTokensInBondingCurve plus either vSolInBondingCurve or vQuoteInBondingCurve
  • bondingCurveProgress when it is actually proven for the pool family
  • marketCapSol for SOL quote paths or marketCapQuote for non-SOL launchpad paths
  • appRiskScorePercent and riskFlags when exposed by the create path

Quote-aware launchpads

Non-SOL quote create fields

  • If quoteMint is not the SOL mint, price is still quote-per-token.
  • Use quoteInPool and vQuoteInBondingCurve instead of forcing the same value into SOL fields.
  • Use marketCapQuote for non-SOL launchpad create payloads unless a separate proven SOL conversion exists.

Known boundary

Progress is not universal

pump-fun bondingCurveProgress is currently treated as proven.
Other families Progress should be treated as null unless the exact formula is proven for that family.

Client guidance

Safe create parsing

  • Use pool and poolProgramId for routing.
  • Do not assume every create field is equally strong across every pool family.
  • Keep conditional values nullable in your own model.
